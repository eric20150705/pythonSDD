# 任務清單：抽取方塊與槍械

**輸入**：`specs/002-pull-block-gun/` 的設計文件

**前置文件**：[plan.md](./plan.md)、[spec.md](./spec.md)、[research.md](./research.md)、
[data-model.md](./data-model.md)、[contracts/ui-controls.md](./contracts/ui-controls.md)、
[quickstart.md](./quickstart.md)、`.specify/memory/constitution.md`

**測試**：本功能規格定義了各使用者故事的獨立測試與驗收情境；憲章要求可分離的
遊戲規則具備聚焦的自動化檢查，實作計畫也要求支撐連鎖與重生回歸測試，因此本清單
包含測試任務。

**組織**：任務依五個使用者故事的優先級排序。每個故事都有獨立測試條件；同一個
單檔程式或測試模組中的任務會明確排序，不會任意標記為可平行。

  `tests/test_game_3d.py` 與 `requirements.txt` 的既有基線命令，並在
  `specs/002-pull-block-gun/quickstart.md` 的基線段落記錄結果。

  完成後執行。

  US1 的抽取拆除與 US2 的子彈拆除已完成（T012、T021）。
- **使用者故事 3（第 6 階段）**：T027–T028 先於 T029–T031，T032 是檢查點；技術上只依賴
  T006 的世界邊界，但為減少單一 `game_3d.py` 的衝突，排在 P1 遊戲故事之後。
- **使用者故事 5（第 7 階段）**：T033 先於 T034–T035，T036 是檢查點；它依賴 T021、T026、
  T032 提供的玩家、子彈、抽取、可見性與重生狀態。
- **收尾（第 8 階段）**：T037 可在故事檢查點後開始；T038 依賴 T039、T040，T041 最後執行。

## 實作策略

### 先完成 MVP

1. 完成 T001–T006，建立基線、狀態邊界、清理規則與不變量測試。
2. 完成第 3 階段 T007–T012，交付安全站立與抽取方塊。
3. 暫停並獨立驗證 US1 測試與手動冒煙路徑。
4. 先展示可玩的 MVP，再加入槍械、遠景與 HUD 擴充。

### 增量交付

1. 加入第 4 階段 T013–T021，交付可切換槍械與十次命中子彈，獨立驗證。
2. 加入第 5 階段 T022–T026，鎖定原有倒塌、重生與計數行為。
3. 加入第 6 階段 T027–T032，交付淺藍天空與有界遠景。
4. 加入第 7 階段 T033–T036，完成 HUD 可理解性。
5. 完成第 8 階段 T037–T041，通過自動、手動與文件品質門檻。

### 實作期間的品質規則

- 每個故事的測試任務必須先於實作任務，並確認新增測試能捕捉預期的未實作行為。
- `demolish_segment()` 必須是唯一拆除入口；玩家接觸碰撞不得呼叫它。
- `active_chunks` 必須是物理與互動的權威集合；`visible_chunks` 只能供渲染使用。
- 所有幀計時器、子彈、碎片、特效與可見區塊都必須有界，適用時不得為負值。
- 不得新增依賴、生命值、彈藥、換彈、音效、勝負狀態或跨場次持久化。
- 移動到下一個故事前先執行該檢查點，並把最終證據記錄在
  `specs/002-pull-block-gun/quickstart.md`。
- 所有 SDD 文件的人工說明文字必須使用繁體中文；程式識別字、命令、路徑與技術名稱
  只有在必要時保留原文，並由 T041 稽核。

## 備註

- `[P]` 表示不同檔案、沒有未完成依賴且可以安全平行處理的任務。
- `[US1]` 至 `[US5]` 對應 `spec.md` 中的使用者故事，便於追溯。
- 每個使用者故事都應能獨立完成與測試。
- 執行測試前先確認測試針對正確的缺失行為；不要用模糊的「完成功能」作為任務描述。
- 每完成一個邏輯群組就提交一次，並在檢查點停止確認。
- 避免同一檔案的衝突修改、模糊任務與破壞故事獨立性的跨故事依賴。
